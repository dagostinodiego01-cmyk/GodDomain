# Art Pipeline — Blender → Unreal

Status: **Proposed** (ADR-020). Companion to `ART_DIRECTION.md` (what it looks like) and `ARCHITECTURE.md` (where files live).

## Roles

| Tool | Owns | Notes |
|---|---|---|
| **Blender 5.3** | meshes, UVs, rigs, source textures, kit `.blend` files | source of truth for anything modelled |
| **`Tools/Blender/generate_textures.py`** | the six base material sheets | numpy only, runs headless or inside Blender |
| **Unreal 5.8.4** | materials, import, level assembly, lighting | UE is where a material becomes a look |

Nothing 3D is hand-authored outside Blender, and no texture is painted by hand until the procedural pass has failed at something specific.

## 1. Units, axes, scale

- Blender: **Metric**, unit scale **1.0**, length **Meters**. 1 Blender unit = 1 m.
- Unreal: 1 uu = 1 cm, so a 2 m wall exports as 200 uu.
- **Apply all transforms** (`Ctrl+A → All Transforms`) before export. Non-uniform object scale is the usual cause of skewed imports.
- Model facing **+Y in Blender**. Confirm the mapping once with the scale test below instead of trusting convention.
- Origin rule: props pivot at their **base centre** (so they sit on the ground when placed); architecture pivots at the **bottom-left corner of its grid cell** (so bays snap together).

**Scale test (do this once, then never think about it again):** export a 1×1×1 m cube as `SM_ScaleTest`, import, and confirm its bounds read 100×100×100 uu. If they read 1×1×1 or 10000, fix the exporter preset before modelling anything else.

## 2. Kit grid

Everything snaps to a 10 cm grid, and building elements use fixed module sizes so pieces recombine. These numbers come from the greybox ranges in ADR-016, so the final kit drops onto existing buildings.

| Module | Size | Notes |
|---|---|---|
| Bay width | 200 cm | Buildings are 3–7 whole bays (620–1400 cm trade shops) |
| Storey height | 320 cm (280 cm slums) | Wall pieces stack to this |
| Wall thickness | 30 cm | Interior faces rarely modelled |
| Jetty overhang | 40 cm | Fronts only; sides stay flush |
| Roof pitch | 50° domestic / 60° towers | Ridge and eave pieces must match |
| Timber member | 20 × 20 cm | Posts, beams, braces |
| Door opening | 100 × 210 cm | Arched variant for civic |
| Window opening | 90 × 140 cm | Small and deep-set by design |
| Tile course | 26 cm | Matches `T_Roof_Tile` at 8 courses per 2 m |
| Cobble stone | 20–25 cm | Matches `T_Cobble` at 9 cells per 2 m |
| Kerb | 150 cm wide × 40 cm high | Matches ADR-015 street carving |
| Step rise / tread | 17 / 30 cm | Seven-step flights per ADR-013 |

## 3. Kit inventory and order of work

Build in this order; each phase is usable on its own and each maps to a level already in `Game/Content/StarterVillage/`.

| Phase | Contents | Count (target) |
|---|---|---|
| **P0 — materials** | the six sheets from `ART_DIRECTION.md` + preview | 6 sheets |
| **P1 — facade kit** | wall bay ×3, corner post, jetty band, X-brace panel, planked infill, door ×2, window ×2 + shutter, dormer, gable roof, hip roof, eave/rafter strip, chimney, balcony rail, timber steps | ~24 pieces |
| **P2 — street kit** | awning (straight + striped), market stall, signboard (no text), lantern post, banner pole, barrel, crate, hand cart, sack pile, well, fountain, statue plinth, bench, planter | ~20 pieces |
| **P3 — civic kit** | colonnade, arched window, buttress, pinnacle, rose window, spire sections, gate tower cap, banner | ~12 pieces |
| **P4 — landscape** | kerb, stair flight, bridge span, dirt/grass transition pieces, tree ×3, shrub, ivy patch | ~12 pieces |
| **P5 — decals** | leaf litter, cobble cracks, moss, soot, standing water, worn paint | ~8 |

Rule: **no new kit piece until the previous phase is imported and lit in UE.** A kit that looks right in Blender's viewport and wrong on the plaza is a lighting-story problem, and it is cheapest to find out early.

**Scope note (ADR-017):** the river, terraces, hills and trees are stripped from the level until the village is signed off, so **P4 landscape stays deferred** behind P1–P3. Foliage that is part of the village itself — window boxes, planters, ivy on walls, leaves on cobble — still belongs to P2 and P5.

## 4. Textures

Generated by `Tools/Blender/generate_textures.py` from `Tools/Blender/palette.json`:

```
python Tools/Blender/generate_textures.py            # all six sheets
python Tools/Blender/generate_textures.py --only T_Roof_Tile --size 2048
```

Output: one folder per material under `Art/Exports/Textures/`, containing `_BaseColor`, `_Roughness`, `_Normal`, `_Height` PNGs and a `preview_materials.png` contact sheet.

Specs:

| Property | Value | Why |
|---|---|---|
| Base resolution | 1024 px over a **2 m** tile = **512 px/m** | That texel density is the target everywhere |
| Hero overrides | 2048 for cathedral stone and plaza cobble | The two surfaces the camera gets closest to |
| Tiling | every map tiles seamlessly at 2 m | One sheet per family, UV-scaled per surface |
| Maps | BaseColor (sRGB), Normal (non-sRGB), Roughness, Height | ORM packing is a later optimisation, not a now problem |
| Colour space | Only BaseColor is sRGB | Grey maps imported as sRGB wash out in UE |
| Naming | `T_<Family>` prefix, `_BaseColor` etc. suffix | Matches `CODING_STANDARDS.md` |

Deliberate constraints:

- Textures are **generated, not painted**, so a colour decision is a one-line JSON edit and a re-run. Reproducible because each material's seed is derived from its name.
- No baked directional light. Sun and shadow belong to the level.
- No text of any kind in any texture (IP rule).

## 5. Export and import

```
Art/Blender/<Kit>.blend          ← source (one file per kit: VillageFacadeKit, StreetKit, …)
Art/Exports/<Kit>/SM_<Name>.fbx  ← one file per mesh, transforms applied
Art/Exports/Textures/<T_*>/      ← generated sheets (gitignored — regenerate, do not commit)
```

`Art/Exports/Textures/` is deliberately ignored: it is reproducible from `palette.json`, so a fresh clone runs the generator once (§4) instead of pulling 13 MB of noise. Mesh exports still commit normally.

- FBX is the primary interchange; keep **glTF (.glb)** as the fallback if FBX scale drifts.
- One mesh per file, `SM_` prefix, `Kit_Element_Variant` naming (`SM_WallBay_Plaster_A`).
- UV channel 0 = tiling (scaled so the 2 m sheet maps 1:1 to 2 m of surface), channel 1 = lightmap.
- Collision: architecture gets simple box collision generated in UE; anything a player walks on or around (stairs, stalls, railings) gets authored convex collision named `UCX_SM_<Name>`.
- Import destination is **provisional** while the `Game/` folder layout is being reorganised — expected to become `Content/StarterVillage/Art/<Kit>/`. Confirm against the layout work before the first import.

## 6. Iteration loop

1. Edit `palette.json` or the generator if the look is wrong; re-run; check `preview_materials.png`.
2. Build or adjust one kit piece in Blender.
3. Export, import, place it against real neighbours at player height in `LVL_StarterVillage_V2`.
4. Compare against `Art/Reference/REF_StarterVillage_MarketSquare_01.png` from the same camera height.
5. Keep it or revert — but do not "improve it later". Unverified pieces accumulate.

## 7. Verification checklist per phase

- [ ] Mesh imports at the intended size (compare against `SM_ScaleTest`)
- [ ] Bays snap with no gaps or z-fighting at a 200 cm spacing
- [ ] Tiling has no visible seam on a 6 m wall
- [ ] Reads correctly at 40 m, not just at 2 m
- [ ] No unique texture where a trim sheet would do
- [ ] Level captured from player height for a visual check

## 8. Known risks

- **Blender is not on `PATH`** on this machine (it runs, but from an install location outside the standard folders). Use the full `blender.exe` path for headless runs, or run the generator with system Python, which is what it is written for.
- **Folder layout in flux** — see §5; don't hard-code import paths into scripts until that lands.
- **Trim sheets are an assumption**, not a proven fit: if the plaza-facing facades end up needing unique wear, that is a hero-facade decision, not a reason to abandon the kit.
- **Foliage is the budget sink.** Three canopy variants, made once, reused; do not model a forest.
